# Webサイトとして公開する手順

`python3 app/build.py` を実行すると、`site/` フォルダに公開用の一式ができます（リポジトリにも入れてあります）。

| ファイル | 役割 |
|---|---|
| `site/index.html` | アプリ本体（単語データも入っている。これ1つで動く） |
| `site/manifest.webmanifest` | スマホの「ホーム画面に追加」でアプリのように使うための設定 |
| `site/sw.js` | 一度開けば、オフラインでも開けるようにする仕組み |
| `site/icon.svg` | アイコン |

サーバー側のプログラムは不要なので、ファイルを置くだけのサービスで公開できます。

## おすすめ：Cloudflare Pages（無料）
1. https://dash.cloudflare.com/ でアカウントを作る（無料）
2. 「Workers & Pages」→「作成」→「Pages」→「Git に接続」で、このリポジトリを選ぶ
3. 設定
   - 本番ブランチ：公開したいブランチ（例：`main`）
   - ビルドコマンド：空欄のままでよい（`site/` はリポジトリに入っているため）
   - ビルド出力ディレクトリ：`site`
4. 「保存してデプロイ」を押すと、`https://〈プロジェクト名〉.pages.dev` で公開される
5. 以後は、ブランチに変更を入れるたびに自動で更新される

独自ドメイン（例：`nyushi-eitango-nine.jp`）を使う場合は、Cloudflare Pages の「カスタムドメイン」から設定します。ドメインは年間1,000〜数千円程度です。

## ほかの選択肢
- **GitHub Pages**：リポジトリが公開（public）なら無料。非公開のまま使うには有料プランが必要
- **Vercel / Netlify**：Cloudflare Pages とほぼ同じ手順（出力ディレクトリに `site` を指定）

## 公開前に決めること・やること
- [ ] **ドメイン名**：ログイン（パスキー）はドメインに結び付くので、ログイン機能を作る前に決める。あとからドメインを変えると、登録済みのパスキーが使えなくなる
- [ ] **プライバシーポリシー**のページ（集める情報：ニックネーム、学習記録。使い道）
- [ ] 有料販売を始めるときは、**特定商取引法に基づく表記**のページ
- [ ] 出典の表記（CEFR-J Wordlist）は、アプリの一番下に表示済み
- [ ] 過去問や記事の英文がサイトに含まれていないこと（単語と自作の意味だけを載せている）

## 今の版の注意
- 学習記録・単語帳・ブックマークは、使っている端末のブラウザの中だけに保存されます。機種変更や別の端末への引き継ぎは、ログイン機能（`docs/ログイン設計.md`）を作ると可能になります
- 無料版（共通テスト）と有料版（大学特化）の切り替えは、まだ誰でも両方使える状態です。課金と合わせて制限を入れます
