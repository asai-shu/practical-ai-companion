# ログインと学習記録の保存（設計メモ・未実装）

方針（ユーザーと決めたこと）
- ニックネーム＋パスキーでログインする。メールアドレスや本名は集めない
- ログインできなくなったとき用に、登録時に「復旧コード」を表示して保存してもらう
- 未成年が使うので、集める情報は最小限にする

## なぜまだ作っていないか
パスキーは「どのドメインのサイトか」に結び付きます（WebAuthn の rpId）。公開するドメインが決まる前に作ると、ドメインを変えたときに全員のパスキーが使えなくなります。**ドメインを決めてから実装します。**
また、Supabase のプロジェクトを新しく作るか、既存のものを使うかは、ユーザーに決めてもらう必要があります（講義アプリ用の既存プロジェクトとは分けるのがおすすめ）。

## 仕組み
```
ブラウザ（site/index.html）
  │ ① 登録：ニックネームを入力 → パスキーを作成
  │ ② ログイン：パスキーで本人確認
  ▼
Supabase Edge Functions（サーバー側の小さなプログラム）
  ・passkey-register-options / passkey-register-verify
  ・passkey-login-options / passkey-login-verify
  ・パスキーの検証には SimpleWebAuthn（@simplewebauthn/server）を使う
  ・検証に成功したら、そのユーザー用のトークン（JWT）を発行する
  ▼
Supabase のデータベース（テーブルは supabase/migrations/ の SQL を参照）
  ・app_users        ニックネーム、復旧コードのハッシュ
  ・passkeys         パスキーの公開鍵（秘密の情報は端末から出ない）
  ・user_state       学習記録・単語帳・ブックマーク（今 localStorage に入れている内容をそのまま1つのJSONで保存）
```

- Supabase Auth 自体がパスキーに対応しているかは、実装時に最新の公式ドキュメントで確認する。対応していれば、Edge Functions を自作せずにそちらを使う
- 学習記録は、ログインしていないときは今までどおり端末の中に保存し、ログインしたときにサーバーの記録と統合する（新しい方を優先）
- 復旧コードは、登録時に1回だけ表示する。サーバーにはハッシュ（元に戻せない形）だけを保存する

## 実装の順番
1. ドメインを決めて、`site/` を公開する（`docs/公開手順.md`）
2. Supabase のプロジェクトを用意し、`supabase/migrations/` の SQL を適用する
3. Edge Functions を4つ作る（rpId に公開ドメインを設定）
4. アプリに「ログイン／登録」画面と、記録の同期を追加する
5. 自分のアカウントで、登録 → 別の端末でログイン → 記録が引き継がれる、を確かめる
6. プライバシーポリシーを載せる
