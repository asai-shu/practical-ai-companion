# ログインと学習記録の保存（設計メモ・実装済み）

方針（ユーザーと決めたこと）
- ニックネーム＋パスキーでログインする。メールアドレス・電話番号・本名は集めない（未成年が使うので、集める情報は最小限にする）
- 2段階認証として、認証アプリ（Google Authenticator など）の6桁のコード（TOTP）を、希望する人だけ有効にできる
- ログインできなくなったとき用に、登録時に「復旧コード」を1回だけ表示して保存してもらう
- 将来の支払いは Stripe Checkout を使う。メールアドレスやカード番号は Stripe 側だけが持ち、このアプリには入れない
- Supabase 標準のパスキーは、試験中のうえ、メールアドレスか電話番号の登録が必須なので使わない

## 仕組み
```
ブラウザ（site/index.html の「アカウント」タブ。Artifact 版には出さない）
  │  fetch（x-session ヘッダーにログイン中のトークン）
  ▼
Edge Function「nine-auth」（supabase/functions/nine-auth/index.ts）
  ・パスキーの検証：@simplewebauthn/server（指紋・顔・PIN での本人確認を必須）
  ・6桁のコード：otpauth（前後30秒のずれまで。同じコードは2回使えない）
  ・呼べるのは ORIGINS のページからだけ（それ以外は 403）
  ▼
Supabase のデータベース（プロジェクト nyushi-eitango-nine。表は supabase/migrations/ の SQL）
  ・app_users            ニックネーム・復旧コードのハッシュ・2段階認証の秘密（AES-GCM で暗号化。かぎは Vault）
  ・passkeys             パスキーの公開鍵（秘密の情報は端末から出ない）
  ・sessions             ログイン中の記録（トークンは SHA-256 のハッシュだけ保存。30日。パスキーだけ通った段階は10分・記録は読めない）
  ・webauthn_challenges  確認用の値（1回きり・5分）
  ・auth_attempts        試行回数（総当たり防止）
  ・user_state           学習記録（端末の localStorage の内容を1つの JSON で。512KB まで）
  ※ ブラウザ用の権限（anon / authenticated）は、どの表にも与えていない
```

## 守りの決まりごと
- 6桁のコードは、まちがえた回だけ数えて、10分に5回まで（正しく入れた人は締め出さない）
- 復旧コードは、まちがえた回だけ数えて、1時間に10回まで（IP ごと）。使ったら新しいコードに取り替え、ほかの端末のログインはすべて終わらせる
- 登録は1時間に10回まで、ログインは10分に60回まで（IP ごと）
- 2段階認証を有効にした人は、やめる・復旧コードの作り直し・アカウント削除にも6桁が必要

## 記録の同期
- ログインしていないときは、今までどおり端末の中だけに保存する
- ログインしたときは、端末とサーバーの記録を「まとめる」（新しい方で上書きしない）。覚えた度合い・復習の段階は進んでいる方、ブックマーク・苦手・単語帳は両方を合わせる、設定は新しい方
- その後は、記録が変わって3秒たったら自動でサーバーへ保存する

## 公開するときにやること
1. ドメインを決めて、`site/` を公開する（`docs/公開手順.md`）
2. `index.ts` の RP_ID と ORIGINS を公開ドメインに書き換えて再デプロイする（RP_ID を変えると、それまでのパスキーは使えなくなる。今は localhost のテスト用）
3. 自分のアカウントで、登録 → 別の端末でログイン → 記録が引き継がれる、を確かめる
4. プライバシーポリシーを載せる
